All endpoints on this page are Platform API endpoints authenticated with `x-api-key` and
require the `execution:read` scope (granted to all keys by default).

## `GET /v2/execution/links`

Deep links to swap venues for buying a token. Use it to power a "Buy" call-to-action:
pick the venues you want to show, render them in any order, and treat `primary` as our
recommendation. Links carry no quote — the venue computes the live price when your user
lands there.

The contract is kind-based: today every link has `kind: "swap"`; future kinds (perps,
pools) will be added under the same shape. `meta.kinds` advertises what the deployment
supports.

- **Scope**: `execution:read`
- **Query params**:
  - `mint` — buy-side Solana mint. Exactly one of `mint` / `assetId` is required.
  - `assetId` — canonical asset id or alias (e.g. `bitcoin`); resolves to the asset's
    primary Solana variant. Unknown ids return `404`.
  - `sellMint` (optional) — overrides the sell side. Defaults to SOL, or USDC when buying SOL.
  - `venues` (optional) — comma-separated venue ids to include. Valid ids: `titan`,
    `jupiter`, `dflow`, `sunrise`, `omfg`, `kamino`, `orca`, `raydium`, `byreal`.
    Unknown ids return `400` listing the valid set.
  - `kinds` (optional) — comma-separated link kinds. Currently only `swap`.
  - `amount` (optional) — sell-side amount as a positive decimal string. Reserved:
    currently accepted but not appended to any venue URL.

```ts
interface ExecutionLinksResponse {
    buyMint: string;
    sellMint: string | null;
    asset: { assetId: string; symbol: string | null } | null; // registry match for the buy mint
    primary: string | null; // our venue recommendation; null when filtered out
    links: Array<{
        id: string; // venue id, e.g. "titan"
        name: string; // display name, e.g. "Titan"
        kind: 'swap';
        venueType: 'aggregator' | 'dex';
        url: string;
        iconUrl: string | null;
    }>;
    meta: { kinds: string[] }; // link kinds this deployment supports
}
```

Some venues drop out per pair instead of erroring: Sunrise (which resolves tokens by
mint but lists a limited asset set) is omitted when the mint has no registry symbol,
and same-mint pairs are omitted where a venue can't express them.

```bash
curl -H "x-api-key: $API_KEY" \
  "https://api.tokens.xyz/v2/execution/links?assetId=bitcoin&venues=titan,jupiter,orca"
```

## `GET /v2/execution/evaluate`

Live quotes from every router we integrate, for one mint at one or more sizes,
ranked, with the edge between them. It answers a single question: **which router
should I send this order to right now, and how much does it matter?**

Quotes are fetched at request time — nothing is cached or sampled.

### Why this is valuable

- **Router selection.** Route each order to whoever is actually best at that
  size. The winner changes with size, so a per-asset default leaves money on the
  table.
- **Best-execution evidence.** Timestamped quotes, plus provider chain context
  where available, are the artifact a desk needs to show it did not overpay.
- **Pre-trade sizing.** Walk the ladder to find where impact turns over before
  you send the order.
- **Router monitoring.** Track `providerStats.wins` and `summary.medianEdgeBps`
  over time to catch a router regressing on your flow.

### Two ways to call it

- **No amounts** — quotes the default ladder (`$10K`, `$100K`, `$1M`), so the
  simplest possible call still returns a useful comparison. `meta.amountSource`
  reports `default`.
- **Explicit amounts** — repeat `amountUsd` (buys) or `tokenAmount` (sells) up to
  9 times.

- **Scope**: `execution:read`
- **Query params**:
  - `mint` (required) — Solana mint. Must be a listed token; unlisted mints
    return `404` (see Limits).
  - `side` (optional) — `buy` (default) quotes USDC → token; `sell` quotes
    token → USDC.
  - `amountUsd` (repeatable) — buy sizes in USDC, each `1` to `50000000`. Only
    valid when `side=buy`.
  - `tokenAmount` (repeatable) — sell sizes in the token's own units, at most
    `token.decimals` decimal places. Only valid when `side=sell`.
  - `providers` (optional) — comma-separated subset of `jupiter`, `titan`.
    Unknown ids return `400` listing the valid set. With one provider there is
    nothing to compare, so every `edge` is `null`.

### How the comparison works

These rules are the contract; pin behavior on them rather than on observed data.

- Both sides are **exact-in**: we fix the input and compare what each router
  returns, so outputs are directly comparable with no normalization.
- Jupiter uses quote-only Swap V2 `/order` with no taker or optional routing
  parameters. Metis, JupiterZ, Dflow, and OKX compete inside Jupiter; the
  fee-inclusive `outAmount` from the winning internal router is what competes
  against Titan.
- The winner is the **greatest `output.rawAmount`**. Ties go to the provider
  named by `meta.tieBreak` (`jupiter`).
- `providerQuotes` is ranked best-first, so `providerQuotes[1]` is the
  runner-up. Unavailable providers trail with `rank: null`.
- `best` is the winning quote hoisted for one-line access. It is always equal to
  `providerQuotes.find(q => q.isBest)`, and is non-null on every `available`
  row — a size with no winner is reported as `unavailable`, never as an
  available row you have to null-check.
- `edge` compares the winner to the runner-up:
  - `bps = (best.output / runnerUp.output - 1) * 10000` — the winner's gain over
    the alternative.
  - `usd` values that gain at the trade's own realized price, so it needs no
    oracle. On sells the output is USDC, so `usd` is the raw surplus. On buys,
    the winner got `X` tokens for `$N` and the runner-up got `Y`, so
    `usd = N * (1 - Y / X)`.
  - The two ratio bases differ by O(bps²) — `12.00` vs `11.99` bps. Both
    formulas are stated here so you can reproduce either.
  - `edge` is `null` when fewer than two providers quoted. It is never `0` in
    that case, because "nothing to compare" is not the same as "they tied".
- Aggregates in `meta.summary` and `providerStats.{meanEdgeBps,medianEdgeBps}`
  cover **contested sizes only** (`summary.comparableEntries`). A median over
  uncontested sizes would report a confident `0 bps` that really means "only one
  router answered". `wins` likewise counts only contested sizes; a size where a
  router was alone is counted in `soleQuotes`.
- Quotes within one response are fetched milliseconds apart. They are not
  atomic or comparable across two separate API calls. `contextSlot` is retained
  when a provider supplies it; Jupiter Swap V2 currently does not.

### Per-provider semantics

The routers do not report the same fields. This is surfaced rather than papered
over:

| | Jupiter | Titan |
| --- | --- | --- |
| `priceImpactPct` | reported from Swap V2 `priceImpact` | **not reported** |
| `priceImpactSource` | `provider` | `unavailable` |
| Route steps | venue labels per hop | venue labels per hop |
| Internal `router` | Metis, JupiterZ, Dflow, OKX, or a future id | not reported |
| `fees` | total and platform fee details when supplied | not reported |
| `contextSlot` | not currently reported by Swap V2 | reported when present |
| Slippage behavior | Jupiter automatic settings | 50 bps |

Jupiter's `priceImpact` is returned in signed percentage points. The endpoint
exposes its magnitude in the existing decimal-ratio `priceImpactPct` field, so
`-98.46` upstream becomes `0.9846` and displays as `98.46%`. The deprecated
Swap V2 `priceImpactPct` field is not used.

The live evaluator never falls back to Swap V1. The separate dark depth sampler
still uses its existing Jupiter V1 client, but those sampled curves are not read
or substituted by this endpoint.

Branch on `priceImpactSource` (or on `priceImpactPct === null`), never on the
provider name — a router that starts reporting impact should not need a client
change. Because impact is not available from every router, **`output.rawAmount`
is the comparable quality metric**, and it is what the winner is chosen by.

```ts
interface ExecutionEvaluateResponse {
    mint: string;
    side: 'buy' | 'sell';
    providers: Array<'jupiter' | 'titan'>; // providers actually queried
    token: { mint: string; symbol: string; name: string; decimals: number; verified: boolean };
    quotes: Array<{
        request: { unit: 'usd' | 'token'; amount: string; rawAmount: string };
        status: 'available' | 'unavailable';
        reason?: 'no_route' | 'timeout' | 'auth' | 'malformed' | 'error';
        // Non-null exactly when status is 'available'.
        best: ProviderQuote | null;   // === providerQuotes.find(q => q.isBest)
        edge: {
            runnerUp: 'jupiter' | 'titan';
            comparedProviders: number;
            outAmountDiffRaw: string;  // integer string, >= "0"
            outAmountDiff: string;     // decimal, output mint decimals
            bps: number;
            usd: number;
        } | null;
        providerQuotes: ProviderQuote[]; // ranked best-first
    }>;
    meta: {
        requested: number;
        available: number;
        unavailable: number;
        deduped: number;              // duplicate amounts collapsed
        upstreamQuotes: number;       // what this call spent upstream
        limits: { maxAmounts: number; maxProviders: number };
        tieBreak: 'jupiter';
        comparisonVersion: string;    // e.g. "quote-compare-v1"
        amountSource: 'request' | 'default';
        defaultLadderUsd: number[] | null;
        tokenSource: 'registry' | 'upstream';
        providerStats: Record<'jupiter' | 'titan', {
            quoted: number;
            unavailable: number;
            wins: number;             // contested sizes only
            soleQuotes: number;       // sizes where it was the only quote
            meanEdgeBps: number | null;
            medianEdgeBps: number | null;
        }>;
        summary: {
            bestProvider: 'jupiter' | 'titan' | null;
            bestProviderReason: 'most_wins' | 'aggregate_edge' | 'only_provider' | 'tie' | 'no_comparison';
            comparableEntries: number;
            meanEdgeBps: number | null;
            medianEdgeBps: number | null;
            maxEdgeBps: number | null;
            maxEdgeAt: { unit: 'usd' | 'token'; amount: string } | null;
        };
        warnings: string[];
    };
}

interface ProviderQuote {
    provider: 'jupiter' | 'titan';
    status: 'available' | 'unavailable';
    reason?: 'no_route' | 'timeout' | 'auth' | 'malformed' | 'error';
    rank: number | null;          // 1-based among available quotes
    isBest: boolean;
    input: Amount | null;
    output: Amount | null;
    effectivePrice: string | null; // output per unit of input
    priceImpactPct: number | null;
    priceImpactSource: 'provider' | 'unavailable';
    route: Array<{
        ammKey: string | null;
        label: string | null;
        percent: number | null;
        inputMint: string | null;
        outputMint: string | null;
        inAmountRaw: string | null;
        outAmountRaw: string | null;
        feeAmountRaw: string | null;
        feeMint: string | null;
    }>;
    contextSlot: number | null;
    router: string | null;        // Jupiter internal router; null for Titan
    mode: string | null;          // normally "ultra" for Jupiter
    fees: {
        feeBps: number | null;
        feeMint: string | null;
        platformFee: {
            amountRaw: string | null;
            feeBps: number | null;
            feeMint: string | null;
        } | null;
    } | null;
    quotedAt: string;
}

interface Amount { mint: string; symbol: string; decimals: number; amount: string; rawAmount: string }
```

### Cost model and limits

Each size is a real upstream quote per provider:

```
upstream quotes = amounts x providers
```

So the default ladder against both routers is 6 quotes; the 9-amount maximum
against both is 18. `meta.upstreamQuotes` echoes what your call actually spent.

- At most **9 unique amounts**. Exceeding it returns `400` — the ladder is never
  silently truncated, because a truncated ladder is a silently wrong comparison.
- Duplicate amounts collapse and are counted in `meta.deduped`.
- Responses are `Cache-Control: no-store`. **Do not call this per keystroke** —
  debounce to a deliberate action, and cache on your side if you need to render
  the same comparison repeatedly.
- `mint` must be a listed token. Unlisted mints return `404` today; that is a
  cost-control boundary, not a bug.

### Failure semantics

A provider that cannot answer is reported, never substituted:

| `reason` | Meaning |
| --- | --- |
| `no_route` | The router found no route. A real market answer. |
| `timeout` | We ran out of time budget before it answered. |
| `auth` | Our credential for that router was rejected. |
| `malformed` | The router's response could not be parsed. |
| `error` | Anything else, including a router we have not configured. |

If one router is slow or down, the other's quotes are still returned — the
response degrades per provider and per size rather than failing as a whole.

```bash
# Default ladder against both routers
curl -H "x-api-key: $API_KEY" \
  "https://api.tokens.xyz/v2/execution/evaluate?mint=cbbtcf3aa214zXHbiAZQwf4122FBYbraNdFqgw4iMij"

# Specific sizes
curl -H "x-api-key: $API_KEY" \
  "https://api.tokens.xyz/v2/execution/evaluate?mint=cbbtcf3aa214zXHbiAZQwf4122FBYbraNdFqgw4iMij&amountUsd=100000&amountUsd=1000000"

# Selling 12.5 tokens, Jupiter only
curl -H "x-api-key: $API_KEY" \
  "https://api.tokens.xyz/v2/execution/evaluate?mint=cbbtcf3aa214zXHbiAZQwf4122FBYbraNdFqgw4iMij&side=sell&tokenAmount=12.5&providers=jupiter"
```

### Errors

| Status | When |
| --- | --- |
| `400` | Missing or invalid `mint`; amount for the wrong side; more than 9 amounts; a buy amount outside `1`–`50000000`; more decimal places than the token has; unknown `providers` value |
| `403` | Key lacks `execution:read` |
| `404` | Mint is not a listed token |
| `429` | Rate limited |
