API v2 is additive: every v1 endpoint keeps working unchanged. v2 currently covers **token lists**,
**risk-aware search / resolve** and **multichain assets**.

- **Base URL**: `https://api.tokens.xyz/v2` — same host and key as v1; only the prefix changes.
- **Auth**: `x-api-key: <YOUR_API_KEY>`; every v2 endpoint needs only the default `assets:read` scope.

Start with the [Quickstart](/docs/v2/quickstart) for one working call per endpoint family, and
[Rate limits & errors](/docs/v2/rate-limits-and-errors) for the envelope and `details.code` values.

## Token lists ("lists as plugins")

A token list is a named, ordered set of Solana mints with an accountable curator. Our curated lists
(`majors`, `currencies`, `rwas`, `etfs`, `metals`, `stocks`, `lsts`) are just the first lists; partner
communities publish their own. Consuming apps explicitly name the lists they trust and compose them into
one corpus — there is deliberately no global "all lists" union, because trust in a curator is the whole
model.

- **Anyone can read** any published list with an `assets:read` API key.
- **Anyone can publish**: every API key can create lists; each list is owned by the
  creating key's project and only that project can modify it.
- Lists may include mints outside our canonical registry; those tokens are flagged `verified: false`
  so your UI can render appropriate caution.

See [Lists endpoints](/docs/v2/endpoints/lists) for the full reference.

## Risk-aware search and resolve

`GET /v2/search` runs every candidate — from a live market-data provider, our token index and the
canonical registry — through a judgment pipeline: hard gates, a weighted score, and explanations
(`reasons`, `warnings`, `badges`). You choose a policy preset (`strict` / `default` / `degen`) and
can override individual gates such as minimum liquidity, minimum age, or `verifiedOnly`. Whatever a
gate removes comes back in `suppressed[]` with the gate that fired, so nothing is silently hidden.

`GET /v2/resolve` answers "which mint is *USDC*?" with a single confident result — or refuses
explicitly (`ambiguous` / `no_confident_match`) rather than guessing.

See [Search & Resolve](/docs/v2/endpoints/search) for the full reference.

## Multichain assets

The v2 asset surface is chain-native: the same curated assets as v1, with their tokens on Solana,
Ethereum, Base, Arbitrum, Polygon and BNB Smart Chain. It has exactly **two nouns**:

- An **asset** is the curated, chain-agnostic thing — `usd`, `bitcoin`, `tesla`. It lives under
  `GET /v2/assets` and `GET /v2/assets/{assetId}`.
- A **variant** is one token on one chain that represents an asset. It has exactly one identifier,
  the key **`<chain>:<address>`** — `solana:EPjF…`, `base:0x8335…` — and lives under
  `GET /v2/variants/{chain}/{address}` and the batch `GET /v2/variants?keys=`.

The rules that follow from that:

- **All chains by default.** An asset's `chains`, per-chain `chainStats`, cross-chain `aggregate`,
  `stats`, `primaryVariant` and `primaryVariantByChain` are always computed from its full variant
  set. `chain=` narrows what is *listed* (which assets qualify, which variants come back), never
  what is *summed*.
- **The chain is always explicit.** A `0x` address is the same string on every EVM chain, so no
  v2 input is a bare address: the chain is a path segment or the key prefix. EVM addresses are
  accepted in any casing and always returned **lowercase**; Solana addresses are case-sensitive
  base58, as ever.
- **No singletons.** v1 synthesised `solana-<mint>` assets for unregistered mints; v2 does not.
  An address-shaped `{assetId}` is `400 invalid_asset_id`, and a token the registry does not know is
  `404 variant_not_found` (or `missing[]` in a batch). Unregistered Solana tokens are the job of
  `GET /v2/search`.
- **Capabilities per chain.** `GET /v2/chains` publishes a capability flag set per chain. Solana has
  everything; the EVM chains have `markets` only for now — no OHLCV, risk, DEX market lists,
  execution quality or swap routing yet — and advisories are keyed by Solana mint. Gate features on
  the flags, not on `chain === 'solana'`.

See [Chains](/docs/v2/endpoints/chains), [Assets](/docs/v2/endpoints/assets) (including the
v1 → v2 field map) and [Variants](/docs/v2/endpoints/variants) for the full reference.
