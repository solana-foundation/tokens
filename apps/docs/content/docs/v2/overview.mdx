API v2 is additive: every v1 endpoint keeps working unchanged. v2 currently covers **token lists**
and **execution** (venue links + depth evaluation).

## Token lists ("lists as plugins")

A token list is a named, ordered set of Solana mints with an accountable curator. Our curated lists
(`majors`, `currencies`, `rwas`, `etfs`, `metals`, `stocks`, `lsts`) are just the first lists; partner
communities publish their own. Consuming apps explicitly name the lists they trust and compose them into
one corpus — there is deliberately no global "all lists" union, because trust in a curator is the whole
model.

- **Anyone can read** any published list with an `assets:read` API key.
- **Anyone can publish**: every API key can create lists; each list is owned by the
  creating key's project and only that project can modify it.
- Lists may include mints outside our canonical registry; those tokens are flagged `verified: false`
  so your UI can render appropriate caution.

See [Lists endpoints](/docs/v2/endpoints/lists) for the full reference.

## Execution

`GET /v2/execution/links` returns venue deep links for buying a token — the building block
for a "Buy" call-to-action in any app. Callers choose which venues to show; we return our
recommendation as `primary`.

`GET /v2/execution/evaluate` compares **live quotes across every router we integrate**
(Jupiter and Titan today) for one mint at one or more sizes: who wins each size, by how
many basis points, and via which route. Use it for router selection, best-execution
evidence, pre-trade sizing, and monitoring a router's performance on your flow.
Jupiter's candidate comes from quote-only Swap V2, where Metis, JupiterZ, Dflow, and
OKX compete before the fee-inclusive output is compared with Titan.

`GET /v2/execution/route` is the asset-level product: given a canonical asset
(`assetId=bitcoin`) and a size, it quotes the asset's variant mints, then
splits the order across them for the best total fill — with the evidence and
an edge-vs-single-variant number attached.

All three require the `execution:read` scope, granted to all keys by default.

See [Execution endpoints](/docs/v2/endpoints/execution) for the full reference.
